# STM32 example

[English](README.md) | [中文](README_zh.md)

A Keil MDK project for the STM32F407, generated with STM32CubeMX. It reads a
HiPNUC IMU over UART (HI91, HI81, HI83) or CAN (J1939) and prints a summary
every 2 s on a serial console. It runs as is on the GK-407VE core board. For
another board, change the pins in CubeMX, or copy `User/` into your own CubeMX
project (see [Porting](#porting-to-your-own-cubemx-project)).

## Folders

| Path (under `hipnuc_f407/`) | Contents |
| --- | --- |
| `hipnuc_f407.ioc` | The CubeMX configuration: pins, clocks, peripherals |
| `Core/`, `Drivers/` | Generated by CubeMX: `main.c`, interrupt handlers, HAL, CMSIS |
| `MDK-ARM/hipnuc_f407.uvprojx` | The Keil project |
| `User/` | The HiPNUC code: `app.c` (the example), `imu_uart.c`, `imu_can.c` |
| `User/hipnuc/` | A copy of the decoder in [`c/hipnuc`](../c/hipnuc); do not edit it here |

`main.c` is the one CubeMX generates, with three lines added in its USER CODE
sections: `#include "app.h"`, `app_start();` and `app_poll();`.

## Quick start

You need Keil MDK 5 with Arm Compiler 6 (Arm Compiler 5 builds the project
too), the STM32F4 device pack (Keil offers to install it when the project
opens), and a CMSIS-DAP (DAPLink) or ST-LINK debugger.

Wiring, at 3.3 V logic levels with a common GND:

| IMU | GK-407VE |
| --- | --- |
| TX | PA3 (USART2 RX) |
| RX | PA2 (USART2 TX) |
| GND | GND |

The console is USART1: PA9 TX, PA10 RX, 115200 8N1. Connect a USB-serial
adapter, or the virtual COM port of a DAPLink.

For CAN, use a 3.3 V CAN transceiver: PB9 to its TXD, PB8 to its RXD, its
CAN_H/CAN_L to the IMU's, and 120 ohms at both ends of the bus. Never connect
CAN_H/CAN_L to the MCU directly.

1. Open `hipnuc_f407/MDK-ARM/hipnuc_f407.uvprojx`.
2. Build (F7) and download (F8). The project uses a CMSIS-DAP debugger; for
   ST-LINK, select it under Options for Target > Debug.
3. Open the console. With the IMU at its defaults (115200 baud, HI91 at 100 Hz)
   it shows:

```
HiPNUC STM32F407 example: IMU on USART2 at 115200 baud, receive by interrupt
IMU: <model>
IMU firmware: <version>
100 Hz  roll -9.8 pitch -0.3 yaw 0.3 | frames 397 crc 0 err 0 dropped 0
```

The LED on PA8 toggles with every summary.

## Settings

- `IMU_INTERFACE` in `User/app.c`: `IMU_UART` (default) or `IMU_CAN`.
- `IMU_UART_DMA` in `User/imu_uart.h`: `0` receives by interrupt, one byte at a
  time; `1` receives by DMA into a circular buffer. Use DMA at 460800 baud and
  above, or when other interrupts keep the CPU busy.
- The baud rate and the CAN bit rate are set on USART2 and CAN1 in CubeMX;
  click GENERATE CODE afterwards. Without CubeMX, edit `huart2.Init.BaudRate`
  in `MX_USART2_UART_Init()` or the prescaler in `MX_CAN1_Init()` in `main.c`;
  CubeMX overwrites those lines when it generates again.
- The IMU's defaults are 115200 baud, 500 kbit/s and CAN node 8 (`IMU_NODE` in
  `User/app.c`).

CAN bit timing at the example's 42 MHz PCLK1 (BS1 11 TQ, BS2 2 TQ, SJW 1 TQ):

| Bit rate | Prescaler |
| --- | --- |
| 1 Mbit/s | 3 |
| 500 kbit/s | 6 |
| 250 kbit/s | 12 |
| 125 kbit/s | 24 |

## Console hints

| Hint | Check |
| --- | --- |
| `no bytes from the IMU` | Power, GND, IMU TX to PA3, and that the IMU's output is on |
| `bytes but no frames` | That the IMU runs at USART2's baud rate and outputs HI91 or HI83 |
| `frames this example does not decode` | The HI83 field selection (`LOG HI83 MAP`) |
| `no CAN frames` | Power, CAN_H/CAN_L, the 120 ohm termination, the transceiver's 3.3 V and GND, the bit rate |
| `HiPNUC messages from node N` | Set `IMU_NODE` to N |
| `CAN frames but no HiPNUC messages` | That the IMU outputs J1939 |
| `CAN did not start` | PB8 must idle high: the transceiver's RXD and its supply |
| No output at all | The console wiring (PA9) and 115200 8N1; the board's 8 MHz crystal (the example stops when the clock does not start) |

In the summary, `err` counts overruns (bytes the UART lost) and restarts of
reception, and `dropped` counts bytes the read buffer could not hold (interrupt
mode; in DMA mode, bytes beyond one buffer are lost without a count).

## Using the data

Add your code in `app_poll()` at `/* use imu here */`. Check the matching
`HIPNUC_VALID_*` bit in `imu.valid` before you use a field; the units are
in the comments of `User/hipnuc/hipnuc_data.h`. On CAN each J1939 message carries one
quantity: `msg` is the latest message, and `imu` collects the latest value of
each quantity.

## Porting to your own CubeMX project

CubeMX settings:

| Setting | UART, interrupt | UART, DMA | CAN |
| --- | --- | --- | --- |
| USART Asynchronous at the IMU's baud rate, 8N1 | yes | yes | |
| USART global interrupt | yes | either | |
| USARTx_RX DMA request: Circular, Byte, memory increment | | yes | |
| Pull-up on the RX pin | yes | yes | yes |
| CAN bit timing for the IMU's bit rate, Automatic Bus-Off Management on | | | yes |
| CAN RX0 interrupt | | | yes |

Then:

1. Copy `User/` into your project. Only the files for your interface are
   needed: `app.*`, `hipnuc/`, and `imu_uart.*` or `imu_can.*`.
2. In Keil, add the `.c` files to a group, and `User` and `User/hipnuc` to the
   include paths. Alternatively, put an `.extSettings` file like
   `hipnuc_f407/.extSettings` next to your `.ioc`: CubeMX then adds them every
   time it generates. Do not start a group name with "User"; CubeMX then
   duplicates its own `Application/User/Core` group.
3. In `main.c`, add `#include "app.h"` in USER CODE Includes, `app_start();`
   in USER CODE 2 and `app_poll();` in USER CODE 3, inside the loop.
4. In `imu_uart.h` (or `imu_can.h`), replace `huart2` (or `hcan1`) with your
   handle in both lines: the `extern` declaration and `IMU_UART_HANDLE` (or
   `IMU_CAN_HANDLE`). For CAN2, also set `filter.FilterBank` to 14 in
   `imu_can_start()`: banks 0-13 belong to CAN1.
5. `app.c` prints to `huart1` and toggles the pin labelled `LED` in CubeMX.
   Change `huart1` to your console UART, and label an LED pin `LED` or delete
   the two `HAL_GPIO_TogglePin()` lines.
6. If your project already defines `HAL_UART_RxCpltCallback()`,
   `HAL_CAN_RxFifo0MsgPendingCallback()` or `fputc()`, move our call into yours
   and delete ours from `app.c`.
7. In Keil, select Use MicroLIB for the example's `printf()`.
8. Build, run, and read the hints.

`imu_uart.c` uses only the HAL UART API, so it builds for other STM32 series.
`imu_can.c` is for bxCAN; series with FDCAN need their own conversion to
`hipnuc_can_frame_t`. On other MCUs, implement the three functions in
`imu_uart.h` (or the two in `imu_can.h`) with your own UART or CAN driver.

For STM32CubeIDE or VS Code, generate the project for that toolchain from a
copy of the `.ioc`, add the `User/` sources and include paths, and link with
`-u _printf_float` so that the summary prints numbers. `app.c` provides
`__io_putchar()` for GCC.

## Only the decoder

The seven files in `User/hipnuc/` build on any C99 compiler: feed received
bytes to `hipnuc_decoder_feed()`, or CAN frames to `hipnuc_can_decode()`. Their
headers describe the calls.

## Maintainers

- `User/hipnuc/` is a copy of `c/hipnuc`. After changing `c/hipnuc`, run
  `sh stm32/sync_copies.sh`. CI checks that the copy is identical, and that the
  Keil project keeps Arm Compiler 6, MicroLIB and the `app_start()` and
  `app_poll()` calls.
- The project was generated with STM32CubeMX 6.18.1, the STM32CubeF4 1.28.3
  package and the "MDK-ARM V5.32" toolchain setting. The Keil settings made
  after the first generation stay when CubeMX generates again: Arm Compiler 6,
  MicroLIB, CMSIS-DAP with Reset and Run, and No Warnings for the
  `Drivers/STM32F4xx_HAL_Driver` group. The HiPNUC groups come from
  `.extSettings`. Check these after generating with a newer CubeMX.
